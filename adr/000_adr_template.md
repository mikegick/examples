# ADR template by Michael Nygard

This is adapted from Michael Nygard's ADR template in [Documenting architecture decisions](http://thinkrelevance.com/blog/2011/11/15/documenting-architecture-decisions). For the sake of this project, I've changed the possible statuses to "in-progress", "completed", and "reverted".

In each ADR file, write these sections:

# Title

## Status

What is the status?

## Context

What is the issue that we're seeing that is motivating this decision or change?

## Decision

What is the change that we're proposing and/or doing?

## Consequences

What becomes easier or more difficult to do because of this change?
